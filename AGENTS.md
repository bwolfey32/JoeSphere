# AGENTS.md

Instructions for AI coding agents working in this repo. Codex reads `AGENTS.md`
natively; for Claude Code, symlink or copy this to `CLAUDE.md`.

## What this is

A static fan site logging Joe Rogan's **publicly announced** appearances — tour
dates, scheduled broadcasts, episode releases — plus **Fan Posts**, a public feed
of fan-submitted clips, and public comments/likes on both. The tracker itself is
still a single-page app with no backend; Fan Posts and comments are the one piece
backed by Supabase (Postgres + anonymous auth + RLS), configured near the top of
`index.html`'s script (`const SUPABASE={...}`, with setup SQL in the comment
above it).

```
index.html                        the entire app (inline CSS + JS)
events.json                       generated by CI — never hand-edit
scripts/fetch-events.mjs          scheduled source fetcher
.github/workflows/update-events.yml
```

## Invariants — do not break these

Several of these look like removable clutter. They are not. Each one is either a
security boundary, a bug that already shipped once, or a legal/ethical guardrail.

### 1. User URLs never reach an `iframe src`

`parseVideo()` whitelists the host, extracts an ID, validates it against a strict
charset, and **rebuilds** the embed URL from scratch. Never pass a user-supplied
string to `src`, and never widen the charset regexes. Attack cases already covered:
`javascript:`, `data:`, quote-escapes, and lookalike hosts like
`youtube.com.evil.com`. Feed-supplied video objects go through `parseVideo0()` for
the same reason — **the feed is untrusted input**. Fan Posts pulled from Supabase
are the same trust category: anyone can `INSERT` a row straight through
Supabase's REST API using the (intentionally public) anon key, bypassing this
page's JS entirely, so post rows are re-validated with `parseVideo0()` on read
too, never trusted just because the app itself wrote them.

### 2. Event listeners bind to data attributes, never `.tab`

Ten controls share `class="tab"`. Binding the type-filter listener to `.tab` made
clicking *Heat*, *Previous*, or *Import* set `filter = undefined`, silently emptying
the entire app. Bind to `[data-f]`, `[data-s]`, `[data-m]`. This bug shipped and
took several rounds to find — do not reintroduce it by "simplifying" the selectors.

### 3. Map pins are sized in screen pixels, not viewBox units

`uiK()` returns viewBox-units-per-screen-pixel; pin radii and heat labels multiply
by it. This looks redundant and is not. Geography scales with the map; UI markers
must not. Hardcoding a unit radius renders a 2.4px pin on a phone — the map looked
completely empty and appeared to be a data bug. Re-plot fires on resize and after
first paint because `clientWidth` reads 0 before layout.

### 4. Auto-synced entries never persist to storage

Entries from `events.json` live in `auto[]`, are re-derived every load, and are
excluded from `save()`. Persisting them would leave cancelled events lingering
forever as stale copies. They are also not user-deletable, since they'd return on
next load.

### 5. Storage adapter must keep all three tiers

`window.storage` (Anthropic artifact host) → `localStorage` (self-hosted) →
in-memory (blocked). Dropping the fallback means a deployed site silently loses
every entry on refresh. `localStorage` is only touched when `window.storage` is
absent.

### 6. Demo data never loads by default

`buildDemo()` generates fabricated entries. It is opt-in behind a button. Publishing
invented appearances for a real living person is misinformation — do not restore it
to the default seed, and do not expand the seed with unverified events.

### 7. Disclosure text is load-bearing

The "unofficial fan project" notices in the header and footer and the
*Unconfirmed* badge are not boilerplate:

- **Unconfirmed** means the event is real but Rogan's attendance is unverified. He
  calls most US numbered cards, not internationals or most Fight Nights. Clearing
  the badge should mean someone checked.
- **Comments on events, Fan Posts, and likes are all public and unmoderated
  before appearing** (there used to be a per-browser private-notes feature; it
  was removed in favor of public comments, so there is no longer a private,
  unpublished annotation option anywhere on the site). The disclosure must say
  so plainly — don't let copy drift back into implying anything here is private.

Do not condense these into a single generic disclaimer.

## Scope boundaries

This tracks **announced, scheduled** events. Do not add:

- Real-time or crowdsourced "sighting" reporting
- Predicted future locations for a named individual — the analysis panel is
  deliberately descriptive (cadence, market share, seasonality) and stops short of
  combining them into a location forecast
- Generated comments, seeded discussion, or synthetic engagement of any kind

## Conventions

- Plain JS, no framework, no build step. Keep it dependency-free.
- All rendered strings go through `esc()`. No `innerHTML` with unescaped input.
- Statistics use Wilson score intervals and median/IQR, not normal approximations
  or means — sample sizes here are small and skewed. Verified against reference
  values; keep the tests if you refactor.
- `scripts/fetch-events.mjs` must exit non-zero if **all** sources fail, so CI keeps
  the last good `events.json` rather than blanking the site.

## Known gaps

- The fetch parsers were tested against fixtures only — youtube.com and
  wikipedia.org were unreachable in the environment where they were written. **Run
  the workflow manually and inspect `events.json` before trusting the cron.**
- Wikipedia table structure shifts occasionally; the parser is defensive but will
  need attention when it does.
- `index.html` is a monolith. Splitting CSS/JS into separate files is a reasonable
  first refactor — but re-verify invariants 1–3 afterwards, since all three live in
  code that a mechanical split will move.
- No tests in the repo. The jsdom checks used during development were ad hoc.
  Porting them to a real test file is the highest-value next task.
